# 삼국시대: 데이터 탐구와 우리 반 AR 박물관

총 6차시, 각 40분이다. 기존 자료조사 결과를 재사용하며 문장 수를 맞추려고 내용을 늘리지 않는다. 데이터 탐구는 3차시로 마치고 AR 제작·관람에 3차시를 사용한다.

| 차시 | 목표 | 40분 운영 | 결과물 |
| --- | --- | --- | --- |
| 1 | AI·데이터 이해와 조사 내용 정리 | 이론 10분 / 기존 조사 정리 25분 / 공유 5분 | 근거 문장과 출처 |
| 2 | 문장을 표로 정제 | 이론 10분 / 표 정리·정제 25분 / 제출 5분 | 모둠 정제 표 |
| 3 | 학급 전체 그래프 | 이론 8분 / 통합 확인·그래프 22분 / 해석·저장 10분 | 1~6모둠을 합친 그래프 하나 |
| 4 | 도형으로 유물 모형 제작 | 관찰 5분 / 설명·시범 8분 / 제작 22분 / 확인·저장 5분 | 태블릿에서 만든 학습용 입체모형 |
| 5 | 해설 녹음과 문제 제작 | 근거·역할 8분 / 해설·녹음 16분 / 문제 11분 / 확인·제출 5분 | 해설 3개·문제 2개 기본, 각 1개 추가 가능 |
| 6 | AR 관람과 개인 퀴즈 | 준비 5분 / 관람 15분 / 개인 퀴즈 12분 / 기록·제출·정답 확인 8분 | 개인 답안·맡은 역할·배운 점 |

5차시 녹음은 한 개당 30초 이내다. 설명할 내용과 출처를 먼저 정하고 구성원들이 나누어 녹음한다. 문제는 보기 3개, 정답 1개이며 정답을 확인할 해설을 연결한다. 6개 모둠 모두 제출하면 학급 문제는 12~18개다. 6차시 마지막 8분에 역할·배운 점을 적고 답안과 함께 제출한 후 교사가 마감하여 정답을 공개한다.

## 화면과 교사 진행

- 표·그래프를 이미 다른 도구에서 끝낸 경우 `/three-kingdoms/ar-sample`의 ‘예제로 AR 바로 체험’을 이용한다. 첨성대 연습 모형, 기존 검증 문장 3개, 문제 2개가 있으며 수업코드·DB·학생 제출을 요구하지 않는다. 예제는 기존 작업을 불러오거나 덮어쓰지 않는다.
- 예제 해설은 [기기의 글 읽기 기능](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)으로 들을 수 있고, ‘내 목소리 녹음’에서 직접 녹음한 뒤 AR 설명점을 눌러 재생할 수도 있다. 글 읽기는 지원 기기의 음성을 사용하며 미지원·실패 시 직접 녹음을 안내한다. 연습 내용은 화면을 나가면 초기화되므로 필요하면 JSON 작업 파일을 받는다. 예제 퀴즈는 실제 학생 점수로 저장하지 않는다.
- 기존 표·그래프 파일은 AR 테스트의 필수 입력이 아니다. 실제 모둠 전시에는 조사한 문장 3~4개를 해설로 옮겨 녹음하고, 그래프 이미지는 원할 때 교사가 첨부한다.
- 학생: `/three-kingdoms/ar-studio`
- 교사: `/teacher/three-kingdoms/ar-studio?step=guide&lesson=4`
- 기존 `hub_code` 등 URL 문맥을 다음 차시에서도 유지한다.
- 교사 안내는 차시별 시간표, 핵심 개념 슬라이드, 시범, 학생 활동 순서다.
- 제작은 모형 → 설명·녹음 → 문제·제출 순서다. 전시를 시작하기 전까지 담당 태블릿에서 미완성 작업도 저장하고 이어 열 수 있다.
- 교사는 수업코드를 등록하고 입장한 학생 중 모둠별 제출 담당 태블릿 한 대를 지정한다. 제출 담당 변경 후 새 담당이 저장된 우리 모둠 작업을 열어 이어갈 수 있다.
- 교사는 전시 시작 → 퀴즈 시작 → 답안 마감·정답 공개 순서로 진행한다. 전시 시작 후 작품·문제는 고정된다.
- 인식 카드 6종 PDF를 출력해 모둠 책상에 놓는다. 학생은 개인 태블릿에서 수업에 입장하고 AR 카메라를 열어 카드를 비춘다. 다른 카드로 옮기면 작품이 바뀐다. 동일 유물을 여러 모둠이 사용했다면 관람할 모둠을 선택한다.
- 개별 작품을 먼저 선택하여 3D 미리보기·카메라 관람을 하는 경로도 있다. 공유 관람에는 작업 파일을 태블릿마다 옮길 필요가 없다.
- 3차시 학급 그래프 이미지를 교사가 첨부하면 관람 화면에서 함께 볼 수 있다.

## 음성 및 저장

배경음과 효과음은 기본 꺼짐이며 각각 켤 수 있다. 배경음은 직접 합성한 짧은 반주를 반복한다. 원래 녹음 파일의 목소리는 변형하지 않는다. 해설 중 배경음은 설정 음량의 12%로 낮아지고, 녹음 중에는 즉시 무음이 되며 효과음도 중단된다. 헤드폰 또는 이어폰을 준비한다.

D1에는 수업·입장·작품 버전·문제·개인 답안과 활동 기록을 저장한다. R2에는 도형 및 녹음이 포함된 모둠 작업과 학급 그래프를 저장한다. 개인 퀴즈는 서버에서 채점하고 제출을 고정한다. 정답은 교사 마감 전 학생 API에 포함하지 않는다. 기기 임시 저장과 JSON 파일은 보조 복구 수단이다.

교사 소유권은 Sites 인증 헤더로 확인한다. 기존 화면의 교사 PIN은 서버 권한이 아니다. 학생은 수업코드·이름 또는 별명·모둠으로 입장하여 서버가 발급한 임의 세션을 사용한다. 제출 담당만 자기 모둠의 제작 원본을 읽고 수정할 수 있고, 공개 관람에는 정답 필드가 제외된다. 버전 비교로 동시 저장 충돌을 알린다.

현재 구현의 학생 입장은 AR 수업 내부 입장이다. Hub의 기존 `student_id`를 인증된 신원으로 사용하지 않는다. Career Log에 새 AR 기록을 전송하거나 기존 Hub 계정과 자동 연결하는 기능은 포함하지 않았다. 개인 활동 기록은 AR 교사 진행 화면에 모인다.

## 실행·배포 경계

`pnpm check`는 단위·서버 흐름 테스트, TypeScript 검사, 브라우저 번들, Sites Worker 빌드를 수행한다. 서버 테스트는 실제 SQLite에 생성된 모든 Drizzle SQL을 적용하며 R2는 메모리 대역을 사용한다. 미완성 저장·이어 열기, 담당 권한 이전, 다른 모둠/수업 접근 차단, 충돌 처리, 전시 고정, 6개 모둠 18문제 통합, 정답 비공개, 개인 채점과 음향 제어를 확인한다.

`.openai/hosting.json`에는 논리 바인딩 `d1: "DB"`, `r2: "BUCKET"`을 선언한다. `db/schema.ts`가 스키마 원본이며 `drizzle/*.sql`과 메타데이터를 함께 배포해야 한다. SQL은 Drizzle로 생성했고 이번 작업에서 운영 데이터베이스에는 적용하지 않았다. 런타임 요청에서 테이블을 생성하지 않는다.

새 공유 API는 `sites-worker/arStudio.ts`에서 처리된다. 정적 GitHub Pages 또는 정적 Vercel 배포만으로는 공유 API가 동작하지 않는다. 현재 Vite 개발 서버에도 D1/R2 에뮬레이터는 연결하지 않았다. 공유 서버가 없으면 성공으로 표시하지 않고 서버 준비 안내와 파일 보관 방법을 보여 준다.

배포에는 DB·파일 저장소와 마이그레이션을 함께 반영한다. 사이트의 기존 접근 설정은 유지하므로, 실제 수업 전에 학생들이 해당 주소에 접근할 수 있는지 확인해야 한다. 운영 인증, 서로 다른 태블릿의 공유 저장·관람·개인 답안, 실제 카메라 인식·마이크·음량은 배포 후 기기에서 확인해야 한다. 자동 테스트는 실제 태블릿 검증을 대신하지 않는다.

기존 2개 설명점 AR 작업은 기존 화면에서 계속 사용할 수 있다. 새로운 제작기는 3~4개 설명점의 기본 도형 작품을 사용한다. 조선시대 수업과 기존 AR 자료실 경로를 유지한다.
